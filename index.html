Inbox

Bank SMS, parsed and ready to file.

Message Inbox

Your Shortcut sends each bank/UPI SMS here. The app pre-fills amount + type, then you pick account + category and tap Save. Messages live only in your encrypted GitHub folder (never in local SQLite); new arrivals wait in a temporary outbox until upload.

iPhone Shortcut setup (2 min)

1. Shortcuts app → Automation → + → Message → set Sender to your bank shortcode (e.g. HDFCBK) or Message Contains “debited” → Run Immediately (no confirmation).
2. Action 1: Get Text from Shortcut Input (this is the SMS).
3. (Optional) Action: Ask for Input / Choose from List for account + category — or skip it and pick them in this Inbox (recommended, since the app knows your real lists).
4. Action: URL-Encode the message text, then Open URL:
YOUR-NETLIFY-URL/index.html?inbox=1&body=[EncodedText]&sender=HDFCBK
5. The app opens, stores the raw SMS, shows its best parse, and waits for you to confirm account/category → Save. Reliability note: iOS sometimes delays or batches Message automations; the Inbox + paste box above is the fallback so nothing is lost.

Install on iPhone (no App Store needed)

This app is installable directly from Safari. No Apple Developer account required.
1. Open your Netlify URL in Safari on iPhone  2. Tap the Share button → Add to Home Screen → Add
3. Launch “Expenses” from the Home Screen — it runs full-screen and works offline.

Encrypted GitHub Backup (pass-style)

Like passwordstore.org: your data is encrypted on this device, then stored as monthly shards (one file per month plus dimensions) in your private repo. GitHub only ever sees ciphertext.
Every push pulls first and merges (union by id, your edits win ties, deletions propagate), so one device never silently wipes another's data.

Sign-in & encryption

Contents read+write on this repo only — create one here. GitHub retired passwords, so the token is the sign-in. Everything here is stored only in this browser; the passphrase never leaves it.

Auto-pull runs only when the remote, token and passphrase are all set and the connection verifies; otherwise it skips quietly.

Help & FAQ

How sync, backup and privacy actually work.

How does sync work with multiple devices?
Your ledger lives on each device. GitHub holds one encrypted file per shard (dimensions + one file per month). Every push pulls first, unions both sides by id (the pushing device wins ties), writes the merged result back locally and to GitHub — so no device silently overwrites another. Empty month files are deleted from the repo.
Clear Database vs Delete Everything — what's the difference?
Clear Database wipes this device and deletes the backup from GitHub, but keeps a deletion log (tombstones), so your other devices drop the data too on their next sync. Messages are untouched.
Delete Everything is the plain wipe: device ledger plus all backup and message files on GitHub, with no tombstones kept. Simpler — but any other device still holding data will re-upload it on its next sync.
Deleted or cleared data came back. Why?
Almost always one of these: (1) another device re-uploaded it — it never got the deletion (see above); push from the device that still has it, or delete it there too. (2) The wipe happened on an older app version that didn't tombstone clears — clear again with this version. (3) Auto-pull on startup replaced your local data with the remote backup — that's its job; turn it off in Settings if you don't want it.
What if I edit the same record on two devices?
The pushing device's copy wins for that record (last push wins overall). Different records never conflict — both are kept. If that creates a duplicate, delete one copy anywhere and sync.
How do I add a new device?
Install the app, enter the same remote URL, token and passphrase, then Pull & decrypt (or enable auto-pull). Pull before pushing anything, so you don't upload an empty ledger over your backup.
What do auto-push and auto-pull do?
Auto-push uploads ~3 seconds after each local change (never during wipes). Auto-pull replaces local data with the backup on startup, only when the connection verifies. Both need the remote, token and passphrase saved.
Who can read my data on GitHub?
Only you. Everything is encrypted on your device before upload; GitHub only ever sees ciphertext. The passphrase lives in this browser and is never sent anywhere. The token only grants read+write on your backup repo. There is no server, no database and no analytics.
Where do inbox messages live?
Each SMS becomes one encrypted file in your messages folder on GitHub, plus a temporary outbox on the device until upload — never in local SQLite. Converting or ignoring updates the remote record; "delete after converting" removes the remote file.
Does the app work offline?
Yes — the ledger is fully on-device and everything except GitHub sync works without a network. Changes queue up (auto-push sends them when you're back, messages wait in the outbox).
